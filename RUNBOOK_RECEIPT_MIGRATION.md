# Runbook: Apply manual Prisma migration for Receipts (SQL)

This runbook describes how to apply the generated SQL migration in Neon (or any Postgres SQL editor). The migration was generated as a manual SQL script because a shadow DB couldn't be used here.

Location of SQL:
- `prisma/migrations/manual-add-receipts/migration.sql`

Pre-requisites
- Take a backup/snapshot of the target database (Neon snapshot or pg_dump). This is essential.
- Prefer applying in a staging database first, then production after verification.
- Ensure you have a maintenance window (DDL changes may lock tables briefly).
- Ensure `scripts/backfill-serial-warranty.js` and `scripts/backfill-receiptfiles.js` are present and tested in staging.

Steps to apply in Neon SQL Editor
1. Open the Neon Console or your Postgres SQL editor and connect to the target database (staging first).
2. Create a database snapshot in Neon (or export a pg_dump) to allow rollback if needed.
3. Open `prisma/migrations/manual-add-receipts/migration.sql` and paste the entire SQL script into the Neon SQL editor.
4. Run the script. Monitor errors carefully. If errors occur, stop and review the first failing statement.

Notes about the generated SQL
- The script contains DDL (CREATE TABLE, ALTER TABLE, CREATE TYPE, DROP TABLE, etc.) and some ALTERs that may drop old tables or types.
- The script was generated by diffing the current `DATABASE_URL` (your Neon DB) and the modified `prisma/schema.prisma`. It may include many schema changes beyond the receipts models depending on differences between schema and DB.
- Because the script is a large diff, review the top-level operations (CREATE/DROP) before running.

Backfill and verification (after successful migration)
1. In the app server environment, install dependencies and run any required migrations for ORM clients:

```powershell
cd 'c:\Projects\betechops'
npm ci
npx prisma generate
```

2. Run the backfill scripts (run in staging first):

```powershell
# Backfill serials/warranty if necessary
node scripts/backfill-serial-warranty.js
# Backfill receiptfiles from existing data snapshot (if present)
node scripts/backfill-receiptfiles.js
```

3. Verify schema objects exist:

```sql
-- Verify new tables
SELECT count(*) FROM "Receipt";
SELECT count(*) FROM "ReceiptFile";
SELECT count(*) FROM "CommissionRecord";
SELECT count(*) FROM "Balance";
```

4. Application smoke checks:
- Start the app (or staging deployment) and run the receipt POST/list/get flows.
- Run the gated E2E script if you have credentials: `node tests/e2e/receipt-upload-check.js` (ensure `S3_BUCKET` and `SENDGRID_API_KEY` are set).

Rollback plan
- If the migration causes issues, restore the DB snapshot taken before applying.
- Manual rollback of DDL is risky; prefer snapshot/restore.

Post-deploy follow-ups
- Configure S3 lifecycle rules if using S3 for `ReceiptFile` retention.
- Add the migration files to your codebase (already committed) and open a PR from the branch for review.
- Add an automated CI job to run the gated E2E tests against staging.
